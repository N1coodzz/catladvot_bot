# Уведомления о сделках кошельков Polymarket

Telegram-бот для двух владельцев. Он читает **публичные сделки** отслеживаемых кошельков и присылает личные сообщения. Торговых функций, доступа к вашим кошелькам и приватных ключей в проекте нет.

## Как работает

- Общий список кошельков: адрес или ссылка на профиль, своё название, заметка.
- Общие для обоих владельцев настройки **на каждом кошельке отдельно**:
  - **Каждая покупка от $X** — сигнал на каждую отдельную покупку не меньше X.
  - **Сумма покупок от $X** — складываются покупки **одного кошелька, рынка и исхода** без ограничения по времени. Когда сумма достигает X, приходит один сигнал, и накопление начинается заново. Например, $120 + $180 + $200 при пороге $500 → один сигнал на $500. Покупки разных исходов не складываются.
- **Каждая продажа приходит независимо от порога** и обнуляет незавершённое накопление покупок соответствующего исхода. Если продажа и ещё не отправленное сообщение о покупке попали в одну обработку, сначала показывается продажа, а устаревшая покупка того же исхода отменяется.
- Включение и выключение уведомлений — **личное**. Добавивший кошелёк сразу подписан; второй владелец включает уведомления сам. Если все отключили кошелёк, бот прекращает запросы к нему; при повторном включении старые сделки не рассылаются.
- В сообщении есть исход, сумма, цена **последней сделки**, время по Москве, название/пометка, кнопки на рынок, профиль и транзакцию. Если API вернул событие позже чем через две минуты, сообщение явно отмечается как запоздавшее.
- Кнопка **Статус** показывает последнее успешное обновление каждого активного кошелька и очередь сообщений. После трёх подряд ошибок API бот сообщает о проблеме, а после восстановления — о возобновлении мониторинга.

## Запуск: Docker на постоянно работающем сервере

Нужен сервер с доступом к `api.telegram.org`, `gamma-api.polymarket.com`, `data-api.polymarket.com` и установленным Docker Compose. Бот использует исходящие запросы, открывать входящий порт не требуется.

1. У [@BotFather](https://t.me/BotFather) создайте бота командой `/newbot` и получите токен.
2. Скопируйте `.env.example` в `.env`, впишите `BOT_TOKEN`. Если пока не знаете Telegram ID, временно поставьте `ADMIN_IDS=1`.
3. Запустите `docker compose up -d --build` в папке проекта.
4. Вы оба пишете своему боту `/start`. Пока ID не внесён в список, бот отвечает числовым **Telegram ID** и не даёт доступ к функциям.
5. Укажите оба числа в `.env`: `ADMIN_IDS=ваш_ID,ID_друга`. Примените настройку командой `docker compose up -d --force-recreate`.
6. Снова отправьте `/start`. В меню нажмите **Добавить**, отправьте `https://polymarket.com/ru/@rn1` или адрес `0x2005d16a84ceefa912d4e380cd32e7ff827875ea`, задайте название, режим и порог.

Проверить работу: кнопка **Статус** или команда `/status`. Логи: `docker compose logs -f bot`. Остановить: `docker compose down`. Данные хранятся в Docker volume `bot_data` и сохраняются при обычном перезапуске и обновлении контейнера. **Не запускайте `docker compose down -v`**, если хотите сохранить настройки и историю уведомлений.

Токен должен оставаться в `.env`. Не помещайте его в архив, репозиторий и сообщения боту. Доступ к управлению ограничен Telegram ID из `ADMIN_IDS`; групповые чаты бот игнорирует.

## Запуск без Docker

Нужен Python 3.11 или новее. Скопируйте `.env.example` в `.env`, укажите токен и ID, затем выполните `python bot.py`. Дополнительные пакеты не требуются. Процесс должен постоянно работать, а файл `data/bot.sqlite3` нужно сохранять при переносе проекта.

До настройки Telegram можно проверить адрес и последние три сделки:

```bash
python bot.py verify-wallet 'https://polymarket.com/ru/@rn1'
```

Тесты: `python -m unittest discover -s tests -v`.

## Что следует знать

- Уведомление появляется после публикации **исполненной сделки** в публичном API. Это не сигнал о выставленной, но ещё не исполненной заявке. Проверка запускается каждые 15 секунд по умолчанию; точную задержку доставки нельзя гарантировать.
- Бот сохраняет обработанные сделки и очередь сообщений в SQLite. После временной ошибки API он догружает события с последнего успешного обхода. После сбоя Telegram повторяет отправку; если процесс оборвётся прямо между отправкой и фиксацией доставки, одно сообщение может прийти повторно.
- В публичных строках активности нет отдельного уникального ID каждой строки. Бот определяет повтор по транзакции, рынку, исходу, стороне, времени, сумме и порядку одинаковых строк в ответе API. При изменении порядка или состава исторических строк со стороны API абсолютную точность различения гарантировать нельзя.
- Настройки режима и порога общие. Их изменение обнуляет недостигнутое накопление для соответствующего кошелька. Уже отправленные уведомления остаются в чатах.
- Для непрерывных уведомлений нужен работающий сервер. Этот архив содержит готовый код, но не токен Telegram и не действующий сервер.
